# AI 作答评分设计

## 目标

在知识点“评估话术”下提供文本作答框。学生可使用系统语音输入法将转写文字填入该输入框；提交后由 DeepSeek `deepseek-v4-flash` 给出形成性评分。

## 范围

- 仅接收文本；不录音、不转写、不上传音频。
- 新增 `POST /api/assessment`，请求为 `{ topicId, answer }`。
- 评分结果为 `{ score, summary, strengths, improvements, topicId }`。
- 不读取或修改本地学习档案、掌握状态或题目数据。

## 服务端契约

服务端以 `topicId` 查找主题。题目、说明、掌握证据和评分锚点均由服务端组装；客户端提供的作答文字不可信，不能覆盖题目、评分规则或输出格式。

请求限制：`topicId` 非空，`answer` 去空白后为 1–500 字。评分端点复用匿名 AI 的本地可用性与按 IP 限流策略；未配置 `DEEPSEEK_API_KEY` 返回 503。

模型调用固定为 `deepseek-v4-flash`、`temperature: 0`、`max_tokens: 500` 和 DeepSeek JSON 输出模式。响应必须经服务端解析并验证：分数为 0–100 整数，概述为非空短文本，优点和改进点均为至多 3 个非空字符串。模型响应不合规则请求失败，不伪造评分。

## 评分规则

提示词声明评分仅供学习参考、不是教师结论或掌握判定。模型按题目覆盖度、史实准确性、措施与作用的因果对应评分；对口语表达与常见错别字宽容，不把“统一六国”作为本题巩固统一措施计分。模型只输出 JSON。

## 界面与可访问性

桌面知识脉络的评估话术下增加带标签的 `textarea`、提交按钮、请求中的禁用状态和 `aria-live` 评分结果区。空答案不发请求。错误在页面内显示；失败后保留作答文字。评分不自动改变“已掌握/暂未掌握”。

## 验证

- 先新增评分模块单测：请求验证、服务器知识上下文消息、模型 JSON 解析与字段拒绝。
- 实现后运行相关 Node 测试。
- 启动本地服务，在浏览器中填写秦始皇题答案并提交，确认请求与评分区行为。
